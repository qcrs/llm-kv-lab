# 01 — Problem / Goal / Contribution Boundary

## Problem

external KV reuse避免重复 prefill，但 raw BF16 KV object大。总成本：

~~~text
T_raw ≈ raw_bytes / BW_io
T_comp ≈ T_encode + compressed_bytes / BW_io + T_decode
~~~

真正问题是 bytes、codec、I/O、PCIe、cache-hit critical path的 crossover。

## Goal

在真实 vLLM+LMCache L2 path：

- reproducible connector/reuse；
- raw FS-L2 baseline；
- deterministic Block-INT8 serialized layout；
- transparent serialize/deserialize；
- exact size evidence；
- cache-hit load/resume；
- Triton kernel and placement map；
- conditional performance conclusion。

## Contributions

不是 quant algorithm novelty。贡献是 engineering completeness、ABI discipline、real object lifecycle、byte truth、placement/crossover/profiling。

## Non-goals

rebuild connector/LMCache、new async framework、L1 compression policy、RDMA/multi-node、pre-D2H Core、beat FP8/TurboQuant、必然 TTFT speedup。

## Falsifiable Hypotheses

H1 fixed format file bytes smaller than raw：format/math决定，若 estimator padding抹掉则失败。
H2 large object may amortize codec：crossover sweep决定。
H3 Triton kernel can be correct/fast in isolation：microbenchmark决定。
H4 actual Serde path may not reduce PCIe：NSYS placement决定。

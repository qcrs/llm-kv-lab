# P2 项目总览与导航

## What

真实链：

~~~text
vLLM paged KV
→ LMCacheConnectorV1 / RequestTracker / slot mapping
→ raw MemoryObj
→ SerdeL2AdapterWrapper
→ custom Block-INT8 serialized temp
→ filesystem L2
→ load / deserialize
→ raw destination / restore vLLM KV
→ cache-hit resume
~~~

## Why

external KV reuse减少重复 prefill，但 raw BF16 object外部存储/搬运大。compression减少 bytes但增加 codec cost；系统问题是 format correctness、object lifecycle、actual placement与 crossover。

## Upstream

vLLM connector；LMCache MemoryObj、Serde、AsyncSerdeProcessor、L2 wrapper、filesystem backend、FP8/TurboQuant、request/slot tracking。

## We

transparent fixed-size Block-INT8 format（quant_group待MemoryObj layout freeze）、serializer/deserializer/estimator/factory、PyTorch/Triton codec、E2E verification、byte invariant、crossover/data movement/profiling。

## Versions

V0 connector/raw FS baseline；V1 Block-INT8；V2 Triton/placement/crossover；V3 layerwise/resource/transfer/pre-D2H optional。

## Success

FSL2-scoped exact serialized bytes、real file、load/resume、quality metrics、negative regimes。End-to-end speedup和first D2H reduction不是Core。

## Non-goals

重新实现 LMCache、声称首次增加 compression、beat TurboQuant、L1 CPU capacity默认提升、RDMA/multi-node/P-D。

## State

BLOCKED_BY_PROJECT1_CORE；Slice NONE。

# P1 项目总览与导航

## 项目是什么

P1 在 pinned vLLM v0.26 runtime 内实现一个 scoped physical KV reclamation subsystem：

~~~text
retention decision
→ worker commits retained physical view
→ worker reports effective length / candidate freed IDs
→ scheduler validates canonical ownership
→ BlockPool reclaims pages
→ future allocation reuses pages
→ original request continues logical decode
~~~

核心不是 eviction policy，而是 logical/physical KV position decoupling、ownership transaction 与 real allocator reuse。

## 为什么做

标准 full-attention path 中，logical num_computed_tokens 同时驱动 model position、seq length 与 KV slot position；request-owned blocks 通常直到结束才释放。若算法“忽略”历史 token，却没有改变 canonical ownership，容量没有回来。

## Upstream Already Provides

vLLM：BlockPool、BlockTable、KV managers、Paged KV、slot mapping、attention runtime、runner/scheduler framework、Triton paged store primitive。

Tangram：effective occupancy、logical/cache position split、worker→scheduler freed-ID protocol、copy compaction reference。

Sparse-vLLM：cache owner 分层和 compaction oracle/invalid atomicity。

## We Implement

- v0.26 scoped reclamation state contract；
- whole-block zero-copy row reconstruction；
- worker/scheduler two-commit safe-free；
- effective allocation/slot/attention semantics；
- allocator reuse tests；
- V2 PyTorch + Triton staged compaction；
- benchmark/profiling/evidence。

## Version Boundary

- V1：whole-block zero-copy reclaim；copy compaction hard fallback。
- V2：token-granular staged compaction；Triton performance 非 Gate。
- V3：runtime hardening；不控制项目完成。

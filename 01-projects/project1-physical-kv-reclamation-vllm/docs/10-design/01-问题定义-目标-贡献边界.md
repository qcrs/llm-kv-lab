# 01 — 问题定义、目标与贡献边界

## Problem

long-context request 的 KV blocks 随序列增长。Paged KV 解决分配碎片和寻址，但 full-attention request 默认仍持有历史 pages。如果 retention policy 只让 attention 忽略 token：

~~~text
logical attention set ↓
physical request ownership unchanged
BlockPool free pages unchanged
~~~

所以项目问题是 logical retention 如何变成 physical reclamation。

## Objective

在 MVP 约束内实现：

- block-aligned retain/drop；
- retained physical page list 重建；
- effective/physical length 单独维护；
- next decode logical position 不变、physical append frontier 缩短；
- worker→scheduler safe-free；
- real released-ID reuse；
- V2 token-level compaction。

## Contribution Boundary

Upstream：allocator、page pool、mapping、runner/attention。

Reference：Tangram lifecycle/semantic，Sparse-vLLM test design，newer vLLM lifetime。

We：scoped integration、transaction contract、uniform state、oracles、Triton staged primitive 与 evidence。

## Success

- deterministic ownership/accounting/reuse Gate；
- original request continues；
- second request receives released page；
- feature off / retention=1 identity；
- negative performance results 可解释。

## Non-goals

- 新算法/SOTA quality；
- per-layer/head ragged paging；
- prefix shared refcount；
- async/spec/graph/parallel MVP；
- CUDA allocator memory release；
- 必然 speedup。

## Hypotheses

H1：在 fixed pool pressure 下，reclaim 会增加 allocator-admissible capacity。反例：accounting 仍按 logical frontier 回补 pages。

H2：shorter retained KV 可能降低 decode attention read cost。反例：metadata/reclaim/compaction overhead 更大。

H3：V2 finer granularity 减少更多 physical tokens。反例不影响 correctness，但可能无 E2E benefit。

这些都必须由分别的 allocator、serving、kernel evidence 验证。

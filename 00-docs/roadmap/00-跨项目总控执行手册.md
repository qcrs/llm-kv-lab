# 跨项目总控执行手册

## 唯一执行顺序

~~~text
NEW_PROJECT_DOCUMENTATION_FINAL_CONTRACT_V1_2
→ P1 M0 Foundation / Source Freeze
→ P1 M1 State Contract
→ P1 M2 Runtime Integration
→ P1 M3 Correctness / Capacity / Release
→ P1-G3 V1_RUNTIME_CORE_DONE gate
→ P2 runtime unlock
→ P2 M0 Environment / ABI / Connector Freeze
→ P2 M1 Raw FS-L2 Baseline
→ P2 M2 Block-INT8 Serde
→ P2 M3 vLLM E2E Reuse
→ P2 M4 Triton Codec
→ P2 M5 Crossover / Profiling
→ Delivery
~~~

P1 M4/M5（V2）可以在 P1-G3 V1_RUNTIME_CORE_DONE 后继续；是否先继续 P1 V2 或解锁并排队 P2，由用户 + ChatGPT Web 在 P1-G3 review 时明确决定。无论如何，同一时间只能有一个 runtime Parent Task IN_PROGRESS。

## P1-G3 V1_RUNTIME_CORE_DONE 定义

必须有 evidence 证明：

- logical progress 与 physical/effective KV occupancy 分离；
- whole-block reclaim 后 worker 不再引用候选 pages；
- scheduler ownership commit 通过 validation；
- freed pages 回到 BlockPool；
- 另一个 request 实际复用 released ID；
- 原 request 继续正确 decode；
- retention=1 feature-off identity；
- 不把 free page 声称为 nvidia-smi HBM 返回。

未满足任一项不得解锁 P2 runtime。

## P2 Core Done 定义

必须有 evidence 证明：

- pinned ABI/environment/connector baseline；
- raw filesystem L2 reuse；
- Block-INT8 fixed-size format 与 PyTorch oracle；
- exact estimator/temp/file/reported byte invariant；
- compressed object load/resume；
- codec quality/limitations；
- 不把 generic Serde 声称为 first D2H reduction。

## 权威层级

技术事实/状态与 Agent 行为分别使用 README 中的两条链。跨项目 CURRENT 决定唯一主项目；项目 PROJECT_STATE 决定唯一 Next Allowed Action。

## Stop Rules

以下任一发生即停止扩大 scope：

- source identity 不一致或 worktree dirty conflict；
- Approved Design 与 fixed source 冲突；
- owner/publication/lifetime 不清；
- correctness oracle 或 feature-off regression 失败；
- P1 candidate page 在 worker live view 未结束前被 free；
- P2 ABI silent fallback、size invariant 不成立；
- 需要把 optional V3 当作 Core 才能继续；
- 结果不支持既定 claim。

失败 evidence 必须保留，回到 Last Good Commit 或 reference-backed fallback。
